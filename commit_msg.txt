Neutralise absolute personal paths: resolve data from the environment

The docs and tools carried the local layout (D:\项目\空洞填补2, D:\项目\3DVideos-distrib,
D:\项目\空洞填补, C:\Users\...\.dsh\...).  Against 34 files and ~130 occurrences:

New lfrd/workspace.py resolves every external location from the environment with a
conventional fallback, so a fresh clone works without editing a file:

  BALLET_DATA_ROOT  MSR Ballet root       <- <project>/data/MSR3DVideo-Ballet, or a
                                             ../../3DVideos-distrib/MSR3DVideo-Ballet
                                             next to the project (this machine's layout)
  SIBLING_ROOT      sibling reproduction  <- <project>/data/sibling
  LFRD_PYTHON       interpreter for tools that shell out <- sys.executable

lfrd/io_utils.py no longer hard-codes the dataset; its default comes from
workspace.default_dataset_root(), which auto-detects the conventional location and otherwise
falls back to <project>/data, so the existing checkout on this machine keeps working
untouched (verified: fill_holes still finds the dataset and reports 23.94 dB).

In the tools, paths that can be derived are now derived (ROOT/sys.path from __file__, the
sibling from SIBLING_ROOT, the interpreter from LFRD_PYTHON) and the rest became documented
placeholders.  Two regex passes over-replaced by matching the sibling prefix inside the
project name ("...空洞填补" inside "...空洞填补2"); all seven damaged locations were found by
grep and repaired, including one tool whose ROOT needed an extra dirname after moving.

Also: README and 接口使用说明.md now document the environment variables and how to check what
was resolved (python -c "from lfrd import workspace; print(workspace.env_report())").

Verification: 715 test assertions and 570 on-disk assertions pass; examples_fill_holes.py
case 1 runs (22.88 dB); tools/show_configs.py, tools/final_compare.py and
tools/verify_no_dl.py all run; tools/scan_paths.py reports 2 remaining absolute paths, both
the standard C:\Program Files / C:\ProgramData defaults inside one archived probe script.
